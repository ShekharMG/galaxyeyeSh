1 Problem Statement

The goal of this project is to detect building damage at the pixel level by comparing satellite images captured before and after a disaster using two different sensor types:

Input Modality Channels Role
Pre-event image Electro-Optical (EO) — RGB 3 Before disaster
Post-event image Synthetic Aperture Radar (SAR) 1 (grayscale) After disaster

This is a binary semantic segmentation task — each pixel is classified as 0 (No-Change) or 1 (Change / damaged).

5 Training Configuration

⚠️ CPU-Only Training — No GPU Available This project was trained entirely on a standard laptop CPU with no dedicated GPU.

Running the full recommended configuration (50 epochs, ResNet34, 256×256) on a CPU would take approximately 4 days of continuous laptop runtime, which is not feasible.

To train all 2,781 samples in a practical timeframe, we made these hardware-driven adjustments:
  • Backbone: ResNet34 → ResNet18 (lighter & faster)
  • Image size: 256×256 → 128×128 (4× fewer pixels per image)
  • Epochs: 50 → 10 (maximum feasible on CPU)

Why High Recall but Low Precision?

Due to CPU hardware limitations, the model is trained for only 10 epochs. At this stage it is in a high-recall, low-precision phase — it broadly predicts "Change" to ensure no real damage is missed. With more epochs (and a GPU), the Dice + BCE loss progressively reduces false positives and raises precision.

The most immediate way to improve results without retraining is threshold tuning (see Section 9).

9 Next Step: Threshold Tuning

The model's final sigmoid layer outputs a probability (0 → 1) for each pixel. By default, threshold = 0.5 — any pixel ≥ 0.5 is predicted as Change.

The Problem with Default Threshold = 0.5

At 0.5, the model predicts "Change" too aggressively — high recall but low precision and many false positives.

How Threshold Tuning Works

Raising the threshold forces the model to predict "Change" only when it is more confident, reducing false positives and improving precision (at the cost of slightly lower recall).

Threshold Effect
0.3 Even higher recall, even lower precision
0.5 Default — current result above
0.6 – 0.7 Fewer false positives → higher precision & balanced F1
0.8 – 0.9 Very high precision, but misses more real changes

Commands to Try

python eval.py --data_path ./ --weights checkpoints/best_model.pth --split val --threshold 0.6
python eval.py --data_path ./ --weights checkpoints/best_model.pth --split val --threshold 0.7
python eval.py --data_path ./ --weights checkpoints/best_model.pth --split val --threshold 0.8
💡 Free ImprovementThreshold tuning requires no retraining — just re-run evaluation. Pick the threshold with the best F1 on val, then apply it to the test set. This is especially valuable in a CPU-only setup where retraining is expensive.

11 Conclusions

  1. A complete end-to-end SAR-EO change detection pipeline was built using a Siamese UNet with ResNet18.
  2. All 2,781 training samples were trained on a CPU with no GPU, completing 10 epochs.
  3. Without a GPU, 50-epoch training would take approximately 4 days of continuous laptop runtime — not feasible.
  4. The model achieves high recall (0.94) — rarely misses real building damage — but precision is limited by CPU training constraints.
  5. Threshold tuning is the immediate next step: raising the decision threshold above 0.5 can significantly improve precision and F1 without any retraining.
  6. With a CUDA-capable GPU, 50 epochs on ResNet34 at 256×256 is expected to yield F1 in the 0.60–0.75 range.
